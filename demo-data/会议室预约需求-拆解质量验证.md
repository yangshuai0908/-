# 会议室预约需求 v1.0

## 1. 业务范围与角色

本功能用于公司内部会议室预约，提供创建预约、查看预约、取消预约三个功能，不包含周期性预约和修改预约时间。

系统有员工和管理员两种角色，管理员同时具有员工的权限。所有预约接口均要求用户登录，未登录返回业务错误码 UNAUTHENTICATED。

预约状态只有“已预约”和“已取消”。创建成功后的状态为“已预约”。

## 2. 创建预约的输入规则

创建接口为 POST /api/reservations，请求字段如下：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| roomId | 会议室编号 | 必填，必须对应已存在的会议室 |
| title | 会议主题 | 必填，去掉前后空白后长度为 1～40 个字符，中文和英文字母均按 1 个字符计数 |
| startAt | 开始时间 | 必填 |
| endAt | 结束时间 | 必填 |
| attendeeCount | 参会人数 | 必填，必须为整数，范围为 1～12，包含两端 |

不满足本节明确规定的字段规则时，返回业务错误码 INVALID_PARAM，不创建预约。

会议室只有“可预约”和“停用”两种状态。只能为“可预约”的会议室创建预约，停用会议室返回 ROOM_UNAVAILABLE，不创建预约。

本文没有规定会议室编号和预约编号的长度、字符集，也没有定义 startAt、endAt 在接口中的序列化格式。

## 3. 预约时间规则

时间比较均以服务器当前时间为准。开始时间距离当前时间不得少于 30 分钟，不得超过 7×24 小时，两个端点均允许。

开始时间和结束时间必须位于同一个自然日，当日可预约时段为 08:00～20:00；允许 08:00 开始，也允许 20:00 结束。

开始时间和结束时间的分钟数只能为 00 或 30，秒数必须为 00。预约时长只能为 30、60、90 或 120 分钟。

违反本节任一规则时，返回 INVALID_TIME，不创建预约。

“自然日”和“08:00～20:00”采用哪个业务时区尚未确定，不能直接假定为浏览器所在时区。

## 4. 时间冲突与预约数量

同一会议室的“已预约”记录之间不允许时间重叠。预约时间区间按左闭右开处理，例如已有 10:00～11:00 的预约时，可以创建 11:00～12:00 的预约，但不能创建 10:30～11:30 的预约。

不同会议室的相同时段不构成冲突。“已取消”的记录不参与时间冲突判断。发生冲突时返回 TIME_CONFLICT，不创建新预约。

每位用户最多同时持有 3 条“尚未开始且状态为已预约”的记录。“尚未开始”指开始时间严格晚于服务器当前时间。管理员也受此限制。

已有 2 条符合上述统计条件的记录时，允许创建第 3 条；已有 3 条时，新建请求返回 RESERVATION_LIMIT，不创建预约。“已取消”和已经开始的预约不计入该数量。

## 5. 查看与取消的权限

查看接口为 GET /api/reservations/{reservationId}。员工只能查看自己的预约，管理员可以查看所有人的预约；员工查看他人的已存在预约时返回 FORBIDDEN。

取消接口为 POST /api/reservations/{reservationId}/cancel。员工只能取消自己的预约，管理员可以取消任何人的预约；员工取消他人的已存在预约时返回 FORBIDDEN，预约状态不变。

上述权限规则必须在接口层生效，不能只依赖页面隐藏按钮。对于查看和取消接口，不存在的预约编号返回 NOT_FOUND。

## 6. 取消预约的业务规则

仅当预约状态为“已预约”，且服务器当前时间严格早于预约开始时间时，才允许取消；管理员同样受时间限制。

取消成功后，状态改为“已取消”，并立即释放该会议室的占用时段。被取消的记录不再计入第 4 节的预约数量限制，但仍可按照第 5 节的权限规则查看。

当前时间等于或晚于预约开始时间时，取消请求返回 CANNOT_CANCEL，状态不变。

对“已取消”预约再次发起取消时，应返回成功还是业务错误，目前尚未确定。

## 7. 创建成功与结果返回

当第 1～4 节的适用规则全部满足时，创建接口保存一条预约记录，并返回 reservationId 和 status；status 为“已预约”，预约所属用户为当前登录用户。

创建成功后需要向预约人发送通知邮件。邮件发送失败时是否影响预约结果、是否重试及重试次数，目前尚未确定。

本文规定的错误码均为业务错误码，没有规定对应的 HTTP 状态码、前端提示文案或页面跳转行为。

## 8. 待业务确认的问题

以下问题尚无业务结论，不得作为已经确定的规则：

- 自然日及可预约时段采用的业务时区。
- 重复取消已取消预约时的处理结果。
- 创建成功但通知邮件发送失败时的处理策略。
- 两个用户同时争抢同一会议室、同一时段时的并发控制方式及失败响应约定。
- 会议室被停用后，对已有未来预约的处理方式。
- 同一请求同时违反多条规则时，业务错误码的返回优先级。
- startAt、endAt 的接口序列化格式。
